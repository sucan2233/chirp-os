# 新增54种鸟：动作能力盘点与统一推进建议

2026-10-26实施更新：M8a＋E0首批开发完成（12种、实际追加158帧），手册能力表达同步更新；构建、分轮核心复测、原生专项及素材审计已完成。全目录3745帧，基础包覆盖23种。后续批次与M9尚未实施；下文较早盘点数字与候选说明保留为历史基线，已实施部分以[M8a/E0交付记录](M8A-E0-ACCEPTANCE.md)为准，未验收边界也列于该记录。

日期：2026-10-26。实现基线：`143217e`；承接规划：`79690e6`。状态：**能力盘点完成，增强制作未开始**。本次完成用户指定的第4项，覆盖新增54种，并附全100种能力矩阵；不实施M8/M9、不新增图集、不改变行为许可或出现概率。

## 1. 结论与统计口径

新增54种不是空白素材：每种都已有3张不同的idle画面、2张理羽画面、8张振翅画面和3张落地画面。后续应优先复用这些原始内容，补动作衔接、物种节奏、必要的增强姿态和运行审核。已有画面也不代表完整生态互动已经开放。

| 项目 | 当前实测 / 源码结果 | 对后续的含义 |
| --- | --- | --- |
| 图集 / 公共帧槽 | 54张PNG、每种34槽，共1836槽 | 这是存储结构，不是1836个动作 |
| 物种内不同画面 | 53种各23张，普通䴓25张；合计1244张 | 只在各物种内部以RGBA去重再求和，不做跨物种去重 |
| 重复槽位超额 | 592＝1836－1244 | 不等于592张待补画；其中含有意共用的飞行/滑翔槽 |
| 显式站立回退 | 53种×8＋普通䴓4＝428槽 | 维持34帧兼容前缀；是否替换某槽应跟随实际动作需求 |
| 普通装饰动作 | 54种覆盖12类idle配置、27个绘制分组 | 分组是代码复用结构，不是生物分类或已验证习性 |
| 完整增强基础包 | 新54种均无10帧包；物理缺口540槽 | 原46种另缺340槽；两者分开排预算 |
| 当前管理行为 | 全54种只允许并支持 `relocate` | 只有素材不能自动开放观察、休息、捕虫、食盘或社交 |
| 侧边停靠 | 新54种中只有普通䴓开放 | 它已有侧停画面与调度，仍不自动取得M9树干访问资格 |
| 手册可收集动作 | 全54种分母均为0，因为换位不计收集 | 不影响手动发现；不应让用户为不支持的动作补进度 |
| “习性”素材预览 | 34种走idle，1种走侧停，19种回到休息画面 | 预览展示与真实桌面idle不一致，需单独评估展示策略 |
| 当前图集解码字节 | 33,435,192字节，约31.89MiB；每帧边长48–128像素 | 不包含命中缓存、对象开销及整应用内存 |
| 参考资料登记 | 48种有逐鸟URL，6种该字段缺失 | 只盘点已有登记，本轮未联网核验；有URL不等于动作考证完成 |

依据：[可复核证据JSON](evidence/expansion-capability-audit-20261026.json)，包括54种逐鸟像素结果、所有重复帧组、100种能力矩阵及输入SHA256。本次是源码/像素盘点，不是动态观感、桌面行为或自然史验收。参考资料字段的缺失仅指`docs/species-expansion-100.json`，不能据此断言整个仓库没有该鸟资料。

## 2. 优先补什么

| 优先级 | 缺口 | 建议需求 | 不在本次结论中自动授予的能力 |
| --- | --- | --- | --- |
| P0 | 素材、能力与预览容易混淆 | 手册用现有支持导出表达“基础素材可预览，尚未开放可收集动作”；避免把0/0解释为所有习性已收齐 | 不重建手册，不因预览产生观察记录 |
| P0 | 19种“习性”选项没有展示已有idle | 对照桌面与预览，决定显示已有片段或明确标注预览范围；复用`GalleryPose`，补对应选择行为验证 | 当前是代码选择策略，不能只凭本审计就宣称界面有故障 |
| P1 | 全54种缺增强基础包与追加片段元数据 | 先做E0样板，明确准备、重点、回收、停顿及两套时序；逐鸟追加必要帧和锚点 | 不把现有3张idle直接改名成10帧基础包 |
| P1 | 原46种通用行为与新54种存在硬边界 | 用逐鸟、逐行为审核名单接入已完成内容；同步准入、执行、导出、手册与完成事件 | 不把54种加入`legacySpecies`以一次性放开所有通用行为 |
| P1 | 物种特色尚未形成完整片段 | 保留体型、纹路和动作方向，分别处理头、尾、翼及支撑脚；复用时序和工具，不复制成品鸟体 | 不用更高触发频率或全图缩放代替动作设计 |
| P2 | 专用生态与自然史证据缺口 | 实施具体互动前，补确切物种的动作参考、宿主/接触和白名单评估 | 食盘、浴盆、捕虫、赠礼、求偶、筑巢不沿亲缘或名称自动扩展 |

统一缺口：`lookNear/lookFar`、`alertRise/alertHold/alertRelax`、`restLower/restTuck/restWake`、`takeoffCrouch/takeoffPush`这10帧在新54种图集中均不存在；也没有导出的增强PoseClip及该包喙锚。支持JSON中的`missingPoseFrames: []`表示“当前没有配置需要检查的姿态包”，不能读成“增强包已完整”。同样，某行为`missingFrames: []`也不代表`productAllowed`或`contentSupported`为真。

重复画面中，全部54种的`bound`与`fly0`相同，`glide0/1/2`三槽相同；普通䴓的`cling0/cling1/peck0`相同而`peck1`不同。它们在不同播放契约下可能有意复用，不能按重复数机械补画。其余428个显式回退也不要求全部变成真实动作：例如没有侧停资格的鸟无需先制作攀附包。

19种预览回退为：丝光椋鸟、八哥、凤头䴙䴘、大鵟、小䴙䴘、小嘴乌鸦、山噪鹛、山斑鸠、棕胸岩鹨、灰斑鸠、灰椋鸟、灰腹噪鹛、环颈雉、白颊噪鹛、角百灵、赤颈鸫、达乌里寒鸦、高山兀鹫、黑尾鸥。源码按`bow/peck/watch/scan`回退，不是这些鸟缺少idle图。

另一个需要先核对的语义点：凤头䴙䴘和小䴙䴘配置为`watch`，但绘制器对`grebe`分组的idle有回首绘制特例。后续不能根据动作枚举就宣称有独立的“观察”片段；必须查看画面并定义实际片段语义。

756＝540帧增强基础姿态＋216帧特色姿态；不含回退槽原位重绘、M9接触帧、道具或自然史参考工作。E0按此情景为60＋24＝84帧，区别于原46种M8a的50＋24＝74帧。若原46种M8与该情景均完成，全目录为3587＋524＋756＝4867帧槽，基础包可达100/100；这只是范围测算，不代表100种全部生态互动完成。M9现有32帧鸟体和20个物件单元仍另计。

按当前图幅大小估算，新54种每鸟追加14帧约增13,767,432字节RGBA（13.13MiB），另有命中缓存和对象开销；不是运行内存承诺。不同体型可能需要不同帧数，应以样板实际完整片段和返工情况修订，不追求统一填满14帧。

## 6. 与原46种、M9和手册统一推进

建议把“当前事实”和“下一步目标”并排维护，不按目录数量自动扩展生产范围：

1. 原46种继续使用[M8逐鸟清单](M8-SPECIES-ASSET-PLAN.md)，本次不改六批名单与524帧预算。新54种由本表补齐盘点，以稳定ID与证据JSON中的`catalogMatrix`连接，形成100种共同视图。
2. 共用管线以原M8a六鸟样板为基础。后续决定启动新54增强时，先考虑E0的六种适配样板，再按依赖将E1–E5穿插到相应旧鸟样板之后；不让54种全部等M9，也不默认挤占原M8b–f交付。
3. 新54种的中性站立、观察、理羽表现不必等待新树干/水岸。E4先解决干燥落点与支撑；实际游泳、触水、取食、攀树访问仍属于单独生态范围。
4. 支持模型要贯通“帧内容→完整片段→逐行为审核→运行资格→实际完成事件→手册支持分母”。新片段仅装饰时，不新设收集成就；经审核接入已有可收集行为时才增加对应分母，预览始终不解锁。
5. M9保持树干→果枝→水岸→同伴回应顺序及当前白名单。普通䴓、拟啄木鸟、鸭类或新斑鸠进入候选不代表自动入场；同名动作或相似外形不替代接触/生命周期证据。

建议先处理的低素材成本事项是：手册0/0的说明、19种已有idle的预览策略，以及扩展种逐行为审核的可维护表达。这些属于下一次开发需求，本次只记录，没有改产品文案、代码或权限。U尚未解释的巢台/赠礼问题仍按主计划定向收口，不在本次盘点中改写成通过。
