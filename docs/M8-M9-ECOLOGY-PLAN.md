## 如何让动作更生动

1. **一个动作有完整过程。** 由观察或准备进入重点动作，再收势和停顿，减少突然切换贴图。新特色包每鸟4帧，配合既有站立、呼吸等帧组成完整片段。帧数是初步预算，样板若证明不足，必须明示调整。
2. **身体部位分别表现。** 小鸟的头、翼尖和尾部有细微错拍；长颈鸟强调颈部曲线、肩部和支撑；长尾鸟用尾部配重；猛禽与鸮类强调凝视、收翼和缓慢回正。禁止仅对整张图缩放、旋转或换色来充当物种动作。
3. **同一只鸟有变化，同种鸟不整齐同步。** 同一素材可用不同停顿、有限循环次数和观察方向，至少准备两种时序编排；选择在开始时由稳定个体seed决定。变化不消耗每帧随机数，不另建timer。
4. **动作回应场景。** 近处有合适物件才探看对应位置；真实接触、取食、取材必须有完整宿主与资格。缺少情境时使用中性观察或理羽，不显示凭空啄到食物。
5. **安静本身有表现。** “活泼”不等于所有鸟都高频跳跃。保留静止、眨眼和不同长度的停顿；点击后的安静期、quiet、暂停及用户节奏偏好继续优先。

样板建议采用两档短/长停顿和有限的动作重复，先在现有机会与冷却机制内试演。不要先全局提频来掩盖素材不足；事件概率、物种出现权重不在M8默认修改范围。必要的节奏调整要按物种记录前后参数及画面理由。

## 素材制作规范

沿用当前原创像素几何与可编辑绘制源，首先核对 [SpeciesArt](../platforms/macos/Sources/Birding/SpeciesArt.swift) 和manifest登记的相关源文件。每种鸟固定色板、体长比例、头身轮廓、喙脚结构及识别花纹，再绘制动作；特别检查绣眼圈、鹊鸲翼斑、红耳鹎冠形、戴胜冠羽、长脚鹬细腿和鸮类头形。

基础逻辑画布保持48×48，既有鸟的实际导出尺寸仍由manifest映射，脚锚保留`(29,39)`。站立姿态固定支撑脚；抬起的脚可以变化，但必须明确支撑脚。真正位移交给现有运动系统，不能让素材和运动系统各移动一次。侧面附着使用已存在的侧面变换与接触契约，不能只凭水平脚锚宣称贴树干成立。

每帧补齐喙锚、有效边界、朝向变换；长尾、伸翼和伸颈在三档缩放均不得截断。公共34帧名称、顺序与已有追加帧保留，新增帧追加。U涉及原46种旧帧像素修正，需先输出差异报告；M8以U交付后的素材为像素基线。M8若再修正旧帧，单列差异与兼容理由，不混入“追加”统计。

外部照片和录像用于动作参考，不直接打包成游戏资产。若后续使用生成图，只用作造型/姿势草图；最终仍需统一像素、透明边缘、连续帧身份、锚点和尺寸。无需为这次计划预先批量生成图片。

每批产出包含可编辑源、图集、manifest、动作映射、并排预览和实际完成统计。镜像、缩放、预览GIF、参考图都不算新增原始素材。图集在载入后复用，禁止每帧重新绘制或解码；资源增长要用实际导出像素和驻留缓存测量，不能只按PNG压缩大小评估。

## 高效验收与完成标准

每批先完成全部代码与素材，再统一导出、编译、验证和验收，遵循项目开发测试要求。计划文档阶段只检查覆盖、算术、链接与差异，不进行应用编译。

| 检查 | 通过标准 | 执行范围 |
| --- | --- | --- |
| 素材完整 | 名单无缺漏，实际帧数与manifest一致，透明边缘正常，旧索引/像素差异有明确解释 | 每批新增物种与受影响导出 |
| 动作可读 | 0.5×/1×/2×及左右朝向可辨识；准备、重点、恢复连贯；实际桌面尺寸下特色可见 | 每种新片段；预览统一生成 |
| 身体与接触 | 无无故脚滑、变体型、花纹闪变、喙穿物或尾翼裁切；位移由单一所有者控制 | 每种；M9新增接触区另验 |
| 生命周期 | 点击抢占、暂停模型、移除、宿主失效、取消后恢复与清理正确 | 对新共用路径完整验证，各物种做映射核验 |
| 确定性 | 同seed同输入在30/60/120Hz下，动作选择和终态一致；单时钟 | 新调度/新场景对应夹具 |
| 性能 | 同机、同鸟数、同场景做前后对照；检查CPU、内存和缓存释放 | M8a、M8总体验收及M9新场景；素材批不重复全套长跑 |
| 实际桌面 | 短时检查正常使用是否打扰、动作是否自然、点击与遮挡是否正常 | 每批重点样本；桌面锁定时不记为已验 |

M8a需冻结性能阈值及同机基线，建议先将CPU p95回归超过10%列为调查门槛；内存依据新增解码图集预算另定，不能承诺素材增加而内存零增长。短时桌面观察建议5–10分钟，作为安排参考，不新增强制长时人工门槛。只有新调度/新宿主出现持续增长或生命周期疑点，才追加有目的的长跑。

实际菜单暂停和系统睡眠未验与核心暂停/睡眠命令测试分开记录；单屏模拟与物理双屏分开记录。没有设备或用户选择保留的项目继续明确未验，不要求用户反复移动鼠标、解锁来凑通过数量。

M8每批完成需同时有素材、映射、实际播放和相应验证证据；全部六批结束后才能写“46种补齐”。仅有524张图或生成预览不算行为开发完成。M9每批还须有完整一次访问、取消和对象清理证据。

## 工作量与首个实施包

M8的524帧约为M6/M7新增167帧鸟体的3.14倍，属于一轮较大的内容扩充；总帧量相对当前1751帧增加约29.9%。帧数不能直接换算为工时：长颈、长腿、侧面接触与小尺寸花纹的返工成本不同。

建议以M8a测量素材绘制、映射、预览修正、测试和实际验收分别用时，再按体态类别外推。M8后续预算为450帧；排期采用样板实测速率与明确的返工余量，不能在样板之前把几百帧承诺成固定几天。

第一个实施包边界已经明确：六种鸟、50帧基础加24帧特色、现有引擎接入、时序变化、预览和统一验收。M8a不依赖新增树干或水岸；大斑啄木鸟使用已有合法侧面宿主，绿头鸭和白鹭做站立动作。M9的物件资格、时长与接触规格在各批开始前冻结，不把M8样板拖成整个生态重写。
