# ChirpOS 概率系统 V2：相对权重与全国鸟种预设方案

- 日期：2026-10-26。
- 交付范围：调研方案已获确认并完成 macOS 实现。按用户 2026-10-26 的最新要求，仅维护 macOS；Windows 仅保留历史源码，不属于本方案的实现或验收范围。macOS 与共享资源镜像采用本方案；实际验证结果与差异见 [V2 实施记录](PROBABILITY-SYSTEM-V2-IMPLEMENTATION.md)。用户真实配置未修改。
- 用户确定的体验范围：中国全国综合体验。包含目录已有的台湾、西北及青藏高原鸟种，使用全年综合视角，不按用户所在地或实际季节自动屏蔽鸟种。

## 1. 结论和现状

按用户补充要求，直接用相对权重替换整个旧百分比机制，默认使用一套系统权重。仅当用户勾选“手动调整概率”时，才展示和应用自定义权重；提供“重置为系统默认值”。不设置逐鸟启用开关、不保留新旧机制切换、不引入权重锁。所有 100 种鸟的系统默认权重均为正。刷新间隔、人口上下限、冷却和候选资格单独管理。

当前资源目录已经给全部 100 种鸟配置了正权重；旧安装中新加入的 54 种鸟默认关闭，主要来自有意保留旧配置的迁移策略，不是资源忘记填值。新安装与从 46 种升级的行为因此不同。

## 2. 概率语义：谁能参与、相对份额、何时发生

对于一次已经确定要进行的选择，设候选集为 E：

```
effectiveWeight(i) = baseWeight(i) × contextMultiplier(i)
P(i | E) = effectiveWeight(i) / Σ effectiveWeight(j), j ∈ E
```

有效权重为 0、缺少该行为能力或场景条件不满足时，不进入相应候选集。V2 首版的物种上下文乘数固定为 1；预留接口，但不暗中加入稀有保底、去重、时间和地域修正。行为人格、冷却等既有权重仍属于它们自己的行为候选池。

例如 A、B、C 权重为 120、60、20，总和 200，占比为 60%、30%、10%。把 B 改为 120 后，A 和 C 的保存值不变，新占比是 46.15%、46.15%、7.69%。所有权重一起乘 10，分布不变。超过 100 的是配置权重，不是某一个事件超过 100% 的数学概率。

| 概念 | 配置/计算方式 | 示例 |
|---|---|---|
| 能否参加 | 有效权重 > 0、资源能力、场景与冷却条件 | 手动权重为 0 的鸟不参加普通入场；不支持群飞的鸟不参加群飞 |
| 候选间如何选 | 相对权重 | 普通入场选物种，群飞选支持的物种，生态事件选参与者 |
| 是否发生 | 成功/失败权重或显式 none | 成功:失败=1:3，等价于发生率 25% |
| 何时有机会 | 时间间隔、人口调度、频率档、冷却 | 不通过物种权重控制每小时入场次数 |
| 动作怎么表现 | 均匀随机数、区间、动画时长比例 | 飞行路径扰动、帧时长份额不是物种概率 |

统一的是随机基础设施和语义契约，不是让所有数值共用一个总权重表，也不是禁止代码中合法的 Bernoulli 概率参数。

```mermaid
flowchart LR
    A[人口或事件调度产生机会] --> B[业务选择策略]
    B --> C[候选资格与能力筛选]
    C --> D[独立基础权重与上下文权重]
    D --> E[共享 WeightedChoice]
    E --> F[选中物种或参与者]
    E --> G[显式 none 或空池结果]
    F --> H[执行前检查空间与冷却]
```

对于已有“抽到不可执行事件即跳过”的调度，需保留其显式 none 分支，不能在 B 中简单删去事件并给其他事件重新分配机会。见第 4 节。

## 3. 可复用底层契约

macOS 新增 `BirdingCore/Random/WeightedChoice.swift`，使用语言无关 fixture 验证权重边界与确定性结果，供各 macOS 领域复用。

```text
WeightedOption<T> { value, weight: Float64 }
ValidatedWeightedPool<T>.init(options) throws ValidationError
choose(pool, rng) -> selected(T) | noEligibleCandidate
bernoulli(successWeight, failureWeight, rng) -> Bool | noEligibleCandidate
uniformIndex(count, rng) -> index | noEligibleCandidate
uniformValue(range, rng) -> value
```

具体约定：

1. 输入权重必须有限且非负；负数、NaN、Infinity、重复候选键是校验错误，禁止静默修正为正常输入。通用池允许零；零不参与抽样。
2. 空池和全零池返回 `noEligibleCandidate`，不退回均匀随机、不自动把零权重改正、不强制解包。手动模式允许全部权重为 0，人口调度因此不再生成新鸟；正在展示的鸟沿用既有离场策略，不为填满人口反复补抽。
3. 物种权重允许 0 或 `0.000001...1000000` 范围内的小数；0 直接表示不参与抽样，不转换成启用标记，也不另存该鸟的上次正权重。恢复出现时输入正值，或整体重置为系统默认值。这个范围是数值与输入保护，不是百分比上限；不约束总和为固定值。
4. 先过滤零，再除以最大权重缩放到 [0,1]，按稳定顺序累计、抽取，避免大数求和溢出。使用补偿求和；边界比较用严格 `<`，浮点尾差仅允许落到最后一个正权重候选。构造器与调用契约仍必须拒绝无效输入，不能用尾差兜底掩盖坏数据。
5. 输入随机数契约为有限的 `0 ≤ u < 1`；测试注入非法 u 返回错误。有效且非空的选择消耗一次随机数，包括单候选；空池不消耗。成功、失败都为零同样是空池，不能当成必定失败或成功而隐藏配置问题。
6. 物种使用显式稳定目录顺序；行为参与者使用稳定实体 ID 顺序，不能依赖 Dictionary/HashSet 遍历。现有目录序与 SpeciesID 枚举序并不相同，实施时明确选用带版本的目录序。
7. 保留已有 EngineRandom/SplitMix64 和分领域随机流（生态、社交、食物、场景等），不要把所有模块改为共享全局随机流。新增 `probabilityAlgorithmVersion=2` 用于回放/诊断；算法或抽取顺序改变后的同 seed 序列不承诺与 V1 一致。
8. 同一有序池及相同注入 u，macOS 各调用方应得到一致结果；完整回放还依赖 RNG、模拟引擎版本与各领域调用顺序。
9. 只读占比由当前候选池计算，不持久化；显示不足 0.01% 时展示“<0.01%”，不误显示为 0。权重极端差异受 Float64/53 位随机数精度约束，不承诺数学上的无限精度或无限小概率。

100 种鸟用 O(n) 累计抽样足够；先不引入别名表、动态缓存失效等额外复杂度。有效池可在配置/场景改变时构造，统一返回诊断原因供开发者排错。

## 4. 对整个项目的适用边界

| 调用域 | V2 接入方案 | 必须保留的语义 |
|---|---|---|
| 普通入场 | 解析系统默认或手动覆盖值，过滤零权重后抽样 | 权重不改变人口上限、入场间隔或鸟的停留时间 |
| 群飞 | 先筛支持群飞且有效权重大于 0 的鸟，再使用相同物种基础权重 | 显示的是群飞候选内占比；不假设所有 100 种都有群飞能力 |
| 生态行为参与者 | 复用 WeightedChoice，以 automaticWeight 等既有行为函数赋权 | 已在场鸟不再乘一次其物种稀有度，避免珍稀鸟连动作也更少 |
| 环境事件类别 | 使用分层权重选择及显式 none | 保留失败、忙碌、禁用和空候选导致的安静时间 |
| 二元触发 | success:failure 权重对；对简单固定事件可保留校验后的概率适配器 | 25% 改写为 1:3，而不是只有一个成功候选 |
| 人口到来/离开 | 中间态 1:1；边界强制动作继续由调度决定 | 不把强制补齐/减少人数变成随机抽签 |
| 均匀选择及数值扰动 | 统一 injected RNG 的 uniform 辅助函数 | 飞行几何、方向与运动扰动不用物种权重 |
| 动画阶段时长 | 保持原逻辑 | LivelyMotion 的 .20/.30/.22/.28 是时间份额，不属于此重构 |
| 鸟种参与判断 | 统一从当前模式解析 `resolvedWeight(id) > 0` | 清理各行为里散落的 `points > 0` 判断，不新增逐鸟 enabled 字段 |

### 环境事件的具体保真设计

目前无聚焦分支先以 8%/4%/1% 选择捕虫/求偶/礼物，剩下 87% 才进入后续选择。功能禁用时相应机会会跳过，不全数让给其他事件。树叶事件在自己的后续分支中有 10% 机会，基础事件再从可用集合均匀选择。

第一层用 `insect:8, courtship:4, gift:1, continuation:87`。前三项关闭或不能执行时返回 none；不移除对应槽位。进入 continuation 后：树叶功能启用时，`leaf:1, base:9`；树叶关闭时直接进入 base，符合当前关闭树叶后落入基础事件的行为。base 从 pointer/flock/social 等已开启集合均匀选，无候选则 none。

因此，在功能都开启且有候选的特定前提下，树叶的总机会是 8.7%，base 为 78.3%；树叶关闭时 base 为 87%。这不是所有场景的全局发生率，还受调度、忙碌和执行条件影响。聚焦分支现有 70% 场景优先使用 `focus:7, continuation:3` 单独描述，不与无聚焦表随意合并。

需要为不同事件域明确 `onIneligible = renormalize | skipOpportunity`。物种候选通常用 renormalize；上述保留安静时间的事件分支用 skipOpportunity。任何改变事件频率的产品调整单独列项，不能混入“底层统一”而无意提高活跃度。

### 刷新频率为何不等于鸟种出现概率

当前 Population 在补齐/缩减人口时使用 2.5–6 秒间隔，正常机会间隔为 24–48 秒；正常机会还可能是离开而不是到来，边界又会覆盖选择。当人口上下限相等、填满后，通常需已有鸟离场才有新的入场机会。Ambient 的低/中/高档另有 180–360、90–180、45–90 秒间隔。暂停、睡眠与忙碌也会减少有效机会。

V2 第一版保留这些节奏。权重说明以“每次有效物种抽样”计，不换算成“每隔几分钟一定来”。屏幕驻留占比还受不同物种停留时间影响，不能与入场占比混为一谈。

## 5. 系统默认值、手动调整和重置

### 界面与模式

整个应用始终运行新的相对权重机制。唯一与自定义有关的勾选项是“手动调整概率”，它决定是否使用用户覆盖值，并控制调整面板的显示，不用于开关概率系统。

| 操作 / 状态 | 界面 | 实际使用的权重 |
|---|---|---|
| 首次安装或旧版升级完成 | 默认不勾选；隐藏鸟种表、权重输入及计算占比，仅显示简短的系统默认提示 | 当前系统默认权重，100 种均为正 |
| 首次勾选“手动调整概率” | 展开调整表，初始显示系统默认值 | 尚未编辑时与默认模式一致；编辑后按已提交覆盖值运行 |
| 手动调整某种鸟 | 该行权重变化、全表计算占比更新 | 只覆盖该鸟的权重，其他鸟保持原值 |
| 取消勾选 | 收起整个调整面板 | 立即回到系统默认语义；已保存的手动值仅作缓存，不参与运行 |
| 再次勾选 | 展开并恢复上次保存的手动值；没有覆盖的条目显示系统默认值 | 使用缓存覆盖值及其余系统默认值 |
| 点击“重置为系统默认值” | 取消勾选、收起调整面板 | 清空所有手动覆盖值，使用当前系统默认；再次勾选也从默认值开始 |

上述切换、重置按现有设置窗口的统一提交机制保存：若窗口具有应用/取消流程，操作先改变草稿及面板状态，点击应用后一次性切换运行模式并落盘；取消或未保存关闭不影响已生效配置。隐藏中的覆盖值不能在默认模式继续生效。

“重置为系统默认值”位于概率设置区，不随调整表一起隐藏；存在手动模式或已保存的覆盖缓存时可用，否则置灰。只重置概率域，不改变人口范围、体型、动画参数等设置。重置清除缓存与取消勾选为同一事务，不出现一半成功的状态。

调整表只有名称、权重输入和只读计算占比，不设逐鸟启用列或锁定列。支持搜索和排序，提示“数值是相对权重，无需合计 100；0 表示不出现”。修改一行不重分配其余行。默认模式不显示这张表，也不展示复杂的行为概率矩阵。

全部手动权重为 0 时显示“当前总权重为 0，新鸟不会入场”，占比显示“—”，底层返回空结果；点击重置或取消勾选可恢复系统默认。不存在单独的“启用全部”操作，系统默认已让全部鸟具有正权重。

### 配置结构与取值规则

建议 schemaVersion=2，继续保留非概率配置。下例仅展示新概率域，不是完整可加载文件：

```json
{
  "schemaVersion": 2,
  "speciesProbability": {
    "manualAdjustmentEnabled": false,
    "overrides": {}
  },
  "migration": {
    "fromSchemaVersion": 1,
    "strategy": "replace-with-system-defaults"
  }
}
```

手动编辑后，例如 `manualAdjustmentEnabled=true`、`overrides={"treeSparrow":150,"peregrineFalcon":0}`。覆盖值按稳定物种 ID 保存；0 是有效覆盖，不能使用“值为真”判断来回退默认值。

```text
if manualAdjustmentEnabled and overrides contains id:
    resolvedWeight(id) = overrides[id]
else:
    resolvedWeight(id) = currentSystemDefaults[id]

resetToDefaults():
    manualAdjustmentEnabled = false
    overrides = {}
```

系统默认表是唯一默认来源，随应用发布，所有已支持鸟种必须具有有限正权重。用户设置只保存手动标记和明确的覆盖项，不复制一份可能过期的默认表。记录 `defaultProfileId/defaultProfileVersion` 作为应用资源元数据及诊断信息；schemaVersion、默认表版本、目录版本、随机算法版本各司其职。

未来版本增加鸟种时，两种模式都从系统默认表取得新鸟权重；不再补 0，也无需新鸟分配预算或自动启用开关。系统默认值更新时，默认模式全部跟随更新；手动模式已覆盖的值保留，未覆盖的鸟跟随系统更新。勾选面板下说明这一规则。手动值恰好等于当前默认值时仍可保留为明确覆盖，避免未来版本悄悄改变用户已指定的值。

首次勾选不批量生成 100 项覆盖；用户实际编辑的条目才写入 overrides。回到默认模式仅停用缓存；“重置”才删除缓存，两者作用明确。

## 6. 旧配置迁移：直接替换为新的系统默认机制

根据用户“直接替换整个机制”的要求，首次从 v0/v1 升级到 V2 时，鸟种概率域统一进入系统默认模式：`manualAdjustmentEnabled=false`、`overrides={}`。旧百分点、旧零值、锁定、新鸟预算和 pendingSpecies 不再作为 V2 的运行配置。**此前方案中的旧比例迁移、逐鸟 enabled 和 editProtected 设计已取消。**

这一规则同时覆盖旧 46 种配置、100 种但新 54 种为零的配置和旧版自定义概率。结果是所有受支持鸟种均取得新的正默认权重，默认不展示调整表。升级说明简短告知“鸟类概率已切换为系统默认权重，可勾选手动调整”，不再提供旧机制/新机制选择器，也不自动导入旧概率为隐藏自定义值。

迁移步骤：

1. 读取并完整校验 v0/v1，保留体型、动画、人口、行为功能等非概率配置。
2. 写入新概率域的默认模式和空覆盖表；新运行模型不携带旧 points、locked、pendingSpecies 或逐鸟启用标记。旧格式仅用于解码及备份，不能继续承担运行抽样。
3. 迁移前备份原始文件，使用同目录临时文件和原子替换写入完整 V2。备份或写入失败时保留原文件，避免丢失旧自定义设置。旧配置备份只用于回滚，不在新界面继续提供旧概率机制。
4. 记录迁移来源与策略。二次加载 V2 不再执行替换，确保用户升级后主动勾选和编辑的值可以跨重启保存；关闭手动模式时其缓存同样持久保存，只有重置才清除。
5. 未知未来 schema 继续拒绝改写；损坏文件进入现有错误/恢复流程，不把解析失败当成正常迁移。V2 的未知物种覆盖项保留但不参与当前候选池，避免目录暂时不识别时丢失数据。
6. 重置为默认值仅清除概率域的 overrides 并关闭手动模式，不重复整个旧版迁移，也不回滚其他设置。以后系统默认表更新，无需再次执行 v1→v2 的替换逻辑。

本方案现已进入实现；用户实际配置未修改。实现只保留新权重模型和必要的旧格式读取器，不保留双轨概率系统，验证记录见配套实施文档。

## 7. 全国初始权重规则和资料边界

本版使用 120/90/65/45/30/18/10 七档，全部为人工设计权重。判断依次考虑国内分布广度、适宜地区常见程度、生境/季节限制和全国体验的地域代表性；保护等级独立展示，不直接当乘数。最高与最低单种比例为 12:1，避免把所有地域特色鸟变成几乎不可见。

数值并非从 2024/2025 年报名次直接计算，也不是把旧权重线性压缩。具体调整如：地方常见的台湾拟啄木鸟、地山雀、欧亚大山雀、黄嘴朱顶雀设为 30；丝光椋鸟、大嘴乌鸦、黑领椋鸟设为 65；高山兀鹫、游隼等为 10。每条设计理由与来源见配套表。

资料能支持常见/局部分布等定性判断；本轮没有得到覆盖全国、标准化努力与季节的原始完整清单，不能估算真实的全国单一遇见概率。eBird 对遇见率的定义依赖标准清单，且要处理地区、季节和观察努力；因此不能把某地观测条数、IUCN 类别或国家保护等级直接换算成游戏百分比。详见配套表的来源与局限。

若以后需要“某城市某季节真实体验”预设，应另立版本：取得合法可用的完整观鸟清单，进行分类对齐、去重、地区/季节与观察努力标准化，留出地区/年份验证，再将估计遇见率做透明压缩映射。不能未经该步骤就宣称本次全国预设已统计拟合。

当前总权重 5358。全部 100 种有资格时，120 权重对应 2.2396%，10 对应 0.1866%；原新增 54 种合计约 48.04%。每种鸟的下次入场机会是独立的，不因长时间没见过而增加。

对固定分布下的一种鸟，平均首次遇见抽数为 1/p，n 次至少遇见一次概率为 `1-(1-p)^n`。10 权重鸟平均约 536 次有效抽样才遇见一次，约 1604 次有效抽样达到单种约 95% 的至少一次遇见概率；这不是全部 100 种齐全概率，也不是分钟数。固定分布下 100/500/1000 次抽样的预期不同鸟种数约为 59.3/95.7/99.1，仍不保证集齐。

首版不加入隐性保底。如果日后想加“探索模式”，应作为独立可选规则，同时展示基础与实际权重；不能让配置页仍声称固定占比。

## 8. 实施顺序和统一验收

按用户开发规范，先完成所有开发，再统一编译、验证和验收。调研阶段只检查文档和数据；随后已按用户授权完成开发与统一验收，实际结果见实施记录。

实施顺序：

1. 固化配置契约、稳定候选顺序、错误/空池行为和共享抽样 fixture；保留法定分类映射待核项为未知标签。
2. 完成 macOS 基础抽样器、V2 数据模型和迁移；保留用户备份和未来版本保护。
3. 更新默认目录/共享镜像和普通入场、群飞、生态选择、二元触发调用；保持事件 none 和时间语义；清理 points 判断。
4. 完成 macOS 默认隐藏的权重界面、“手动调整概率”勾选及重置交互；移除锁定和新鸟预算界面，更新帮助及设置验证逻辑。
5. 全部实现后统一编译与下表验证，最后以旧 46 种用户配置和实际 100 种资源进行人工验收。

| 验收类别 | 必须覆盖的结果 |
|---|---|
| 抽样边界 | 空池/全零返回空；零项不命中；单项必命中；累计分界 u=0、临界点及最大合法值；非法值拒绝 |
| 权重契约 | 修改一个值不改其余值；共同倍乘分布一致；零权重和能力过滤后的分母正确；手动值为 0 不回退默认；浮点极端范围可处理 |
| 分布校验 | 固定 seed 的大样本频率与目标值在事先确定的统计容差内；不以每种必须精确计数作测试 |
| 兼容性 | 46 种旧文件、100 种且 54 个零值、旧自定义值、pending 清空/手动编辑、锁定及 v0 均一次性替换为系统默认概率；未知未来版本拒写；损坏/写盘失败保留原文件；二次迁移幂等 |
| 系统默认 | 100 个稳定 ID 均取得正默认权重；首次安装/旧版升级均不勾选手动调整；其他设置保留；无逐鸟开关、锁定或新旧概率机制切换 |
| 行为语义 | 群飞仍只支持其能力集合；生态参与者不乘物种稀有度；禁用事件、focus、叶子开关、忙碌、无参与者的 none 路径保持既有机会率 |
| 人口与时间 | 手动全零不循环补鸟；固定人口上下限、满员、暂停、睡眠无补发突发事件；权重更改不改变时间参数 |
| 共享契约 | 有序权重/u/预期结果 fixture；迁移输入输出含 ID、手动模式及覆盖值；macOS 各调用方遵循同一抽样契约 |

| 资料 | 100 唯一 ID 与资源一一对应；引用可追溯；不将 NR 写成 NE，不把三有写成三级，不把未匹配写成无保护 |

测试重点更新 `ExpansionTests.swift`、`SettingsVerification.swift` 等 macOS 设置/配置测试，替换依赖“总和10000、默认新鸟零值、修改时重分配”的旧断言。保留非概率功能回归范围；不能为了通过测试删除原有行为能力约束。
