# ChirpOS macOS 下一阶段规划

更新：2026-10-24；历史实现基线：`0ec8378`（M5n）；状态：用户已授权 M6–M7 全量开发，分阶段实施中。实际完成证据见 [实施进度](IMPLEMENTATION-PROGRESS.md)。

## 1. 当前结论与范围

现有运行时适合继续扩展，保留单一模拟时钟、行为生命周期、预约、确定性输入重放和平台快照输出。下一阶段的主要缺口是动作表现、内容配置的一致性及实际桌面验证，不需要重写整个引擎。

仅推进 macOS。Windows 引擎迁移、双端行为对齐和 Windows 原生验收移出当前范围；不删除现有 Windows 实现。共享素材仍保留命名和旧帧索引兼容，macOS 新功能不再等待 Windows 对应实现。

2026-10-24 用户已恢复持续开发，范围覆盖全部 M6a–M6h 与 M7a–M7d；从 M6a 按依赖推进，每阶段实现完整后统一验证、验收和本地提交。

## 5. 调研结论与来源边界

调研见 [求偶/筑巢证据](research/COURTSHIP-NESTING-EVIDENCE.md) 与 [浴盆/捕虫/食盘证据](research/SPECIES-ACTIVITY-EVIDENCE.md)。记录了确切物种、学名对照、来源、正文支持内容与不能推出的结论。

- 珠颈斑鸠的颈部鞠躬展示、衔材与浅盘枝巢有物种资料及中国野外研究依据，三个 M7 批次选定同一物种。
- 麻雀和白头鹎各有水浴记录，浴盆首版确定为两种。
- 家燕采用空中捕食方向，白眉姬鹟采用栖点出击方向；返回原点是产品收尾编排，未把它写成已证实的每次必然习性。
- 灰喜鹊礼物与麻雀叶片游戏是明确风格化内容；不会拿喜鹊、灰喜鹊、家麻雀、树麻雀互相替代证据。
- 概率、秒数、材料数量、槽位、返回规则都是产品参数；素材像素和实际观感必须在实现批次验收，不能用文献代替渲染/性能证据。

## 6. 交付顺序与完成标准

M6a 稳定性/内容契约 → M6b 四鸟姿态 → M6c 十二鸟与支持扩展 → M6d 浴盆 → M6e 携带 → M6f.1/f.2 两种捕虫 → M6g 礼物 → M6h 日常桌面验收；随后 M7a 求偶 → M7b 运材 → M7c 筑巢 → M7d 整体验收。

每个批次的前置条件、状态时序、超时、对象寿命、开关默认值、来源计数、取消与保存语义已写入实施规格。每批代码和素材全部完成后统一编译、验证、原生验收；主会话集中整合共享类型，子 agent 不各自启动互相干扰的原生检查。中文 Conventional Commit，本地提交，不自动推送。

真实物理多屏热插拔、睡眠唤醒、2h 日常观察与8h长时运行是交付要求；无硬件证据的项目不得标已验收。完成标准仅覆盖 macOS。当前已恢复 M6–M7 全量实施；阶段状态见实施进度，不把规划计作已实现。

M6f.2阶段验收通过：Release79.40s、严格签名、3322原生鸟/1820设置、模拟v15的54完整回放、旧17报告不剔字段完全一致、46鸟历史像素/索引不变（恰增白眉3帧，无新道具）、parity、78 GIF/7800帧/loop0及18次性能通过。核心证据是第三轮完整876项中其余875项通过（142.466s）＋第四轮白眉16项全通过（6.981s），不声称单次876全绿；前三轮失败及≤4ULP测试断言修正见[M6f.2验收](M6F2-ACCEPTANCE.md)，生产代码未因测试修正改变。M6f.1→M6f.2三组medianP50变化+1.973684%/−0.669912%/−1.891235%，metrics/cleanup均一致。六组native与中英controls/英文journal已查看，0.5×虫点可追踪但细节难辨，深色背景不替代杂乱桌面。随本阶段记录本地提交、未安装，用户开发包仍为M6a/b；下一阶段M6g，整体目标继续进行。性能仅为同机核心模拟，不替代上述长期与硬件验收。
