# macOS 行为内容实施规格 v1

更新：2026-10-24。状态：**设计已定、待实现**；代码基线 M5n / `0ec8378`。本文件明确后续 agent 的实施边界，不表示功能已经上线，也不恢复暂停中的开发。

## 1. 文档优先级与范围

- 当前实现证据：`BEHAVIOR-ENGINE-DESIGN.md` 第 21、34 节。
- 后续实施契约：本文件；逐鸟支持目标见 [鸟种交付矩阵](SPECIES-DELIVERY-MATRIX.md)。概要见 [路线图](MACOS-BEHAVIOR-ROADMAP.md)。
- 自然行为事实与出处：`research/` 中两份调研记录。事实不决定游戏概率、持续时间或默认开关；本文件所有数值均为产品初值。
- 仅 macOS；继续使用现有 46 个物种 ID，不新增第 47 种。不新增性别、生育、饥饿、健康、季节繁殖或必须照料机制。
- “目标支持”是必须交付的范围，不是当前能力。不得用通用站立帧冒充完成；若真实素材/几何验证不通过，报告阻塞并更新决策，不自行换鸟种或删功能。
- 本轮定清功能、物种、接口边界、初始参数和验收；姿态像素与真实桌面观感在对应实现批次验收，允许调节表现参数，但需记录前后数值及理由。

## 2. 架构与公共实施契约

### 2.1 单一内容配置

新增 `SpeciesBehaviorProfile`，以 `SpeciesID` 为键，集中**现有六种专用行为名单、新行为名单、姿态片段映射**。通用动作仍沿用已有能力检测；不得把此次六种名单集中误当成取消其他通用行为。过境名单 `AmbientFlock.species` 也迁入单一配置，但集合与排序不变。

配置采用类型化 Swift 常量，不引入外部脚本、解释器或编辑器。`BirdCapability` 表示完整必需帧；profile 表示产品允许；executor 检查当时的空间、宿主、所有权、开关与冷却。设置页、预览拒绝提示、支持矩阵导出读取同一配置。

新增 `PoseClip`，包含稳定 ID、帧名与每帧时长、允许循环次数、脚锚、每帧喙锚、恢复姿态。坐标统一为现有 48×48 逻辑画布；素材原始分辨率由 manifest 映射。左右镜像通过与 `BirdRenderState` 相同的变换处理，脚锚保持 `(29,39)`。不在 AppKit 层推进计时或偷偷移动身体来对齐接触。

行为拥有姿态期间，`SpeciesBehavior` 周期闲置输出让出控制权；释放后按引擎当前状态恢复。仅 `watch/alert/rest/takeoffPreparation` 的可选增强允许退回既有表现；求偶、洗澡、携带、捕虫、筑巢缺必需帧直接拒绝 `missingFrames`。

### 2.2 生命周期与优先级

- 鸟只使用已有居民，预览也不补生、不传送；新场景不改变鸟数、用户鸟种权重和屏外入场规则。
- 点击鸟的换位始终可抢占；禁用、移除鸟、关掉场景、宿主失效、显示器变化、睡眠和退出都必须走取消与资源释放。对方鸟独立恢复，不强制追随被点击者。
- 用户暂停冻结行为年龄、道具寿命、冷却、附着与粒子；无效宿主/被删除对象仍立即处理。新行为暂停时禁止启动；既有点击换位语义保留。
- 场景对象与一次访问分开：`HabitatObjectStore` 管放置/寿命/剩余资源，`BehaviorRuntime` 管鸟和槽位租约，`HabitatJourney` 管有界路线。新行为不得另造移动积分器。
- 新接触动作优先级 30，求偶/捕虫/携带/礼物/筑巢为 60；均不可抢占其他运行。数值优先级不自动授予抢占权。
- 一次 run 只能有一个 completed/cancelled/failed。`rejected` 不创建 run。超时是 failed，不把超时或丢失目标伪装成成功。
- 新功能不允许同时占有两只鸟以外的参与者；新显著场景全局最多一个。单个水花最多 6 个，昆虫最多 1 只，附着物每鸟最多 1 件，未放下的材料不可复制。

### 2.3 自动机会与概率（M6d 开始启用）

保留唯一 `AmbientScheduler`，区分日常模式与用户主动放置场景后的短时场景模式。两模式互斥，不叠加 timer；暂停/quiet 不启动新自动动作，忙碌或资格不足的机会丢弃、不排队重试。以下均为明确的产品初值。

**日常模式：** 保持现有低/中/高 180–360s / 90–180s / 45–90s 机会间隔。每次既有机会抽一个固定区间的新事件，剩余区间进入现有选择器。未交付/关闭/不满足条件的区间为空机会，不将概率转给别的新增行为。

| 新行为 | 日常机会区间 / 比例 | 自动资格 | 单鸟冷却 / 全局同类冷却 |
| --- | --- | --- | --- |
| `insectCatch` | [0,0.08)，8% | 有可用家燕或白眉姬鹟及昆虫入场路线 | 180s / 90s |
| `courtshipDisplay` | [0.08,0.12)，4% | 两只珠颈斑鸠满足双鸟条件 | 600s / 300s |
| `visitorGift` | [0.12,0.13)，1% | 用户开启礼物、有符合条件的熟客、静止叶片和空闲接收栖木 | 见礼物章节 |
| 已有事件 | [0.13,1)，87% | 保留已有选择器 | 保留现有规则 |

**场景模式：** 用户放置浴盆、静止叶片或巢台时，取得唯一 sceneFocus；存在另一个 focus 时放置返回 busy。将同一 scheduler 的剩余等待缩短至 `min(remaining,10s)`（不立即起飞），随后低/中/高间隔为 30–45s / 20–35s / 15–25s。每次机会以 70% 仅尝试 focus 对应动作，30% 进入已有选择器；暂不尝试日常模式的捕虫、求偶和礼物。没有可用鸟或空间仍丢弃机会。该有限时长的提频来自用户放置场景，不是多个功能的计时器叠加。

| focus | 选择的动作 | 单鸟冷却 / 全局同类冷却 | 结束条件 |
| --- | --- | --- | --- |
| 浴盆 | `bathVisit` | 45s / 20s | 300s 到期、三次成功洗澡或用户清除 |
| 静止叶片 | `leafCarry` | 45s / 20s | 成功放下、180s 到期或用户清除 |
| 巢台 | 有已送达未整理枝条则 `nestBuild`，否则 `nestMaterialCarry`；仅 M7b 阶段只运材 | 两行为共享 20s / 15s | 900s 到期、完工/材料已无法继续或用户清除 |

focus 结束后同一 scheduler 重置为日常档下限，无积欠机会；道具的收尾展示可继续存在，但不继续提频。场景无合格物种时设置显示所需鸟种，不修改用户概率。成功叶片放下后可成为日常礼物原料；因此其可见停留延长至 600s，只有已开启礼物时生效，否则仍为 8s。礼物资格始终按“已放下、可拾取、未被占有”的状态检查。

现有 `AmbientScheduler.suppress()` 的 60s 下限须区分原因：普通互动完成/预览在 scene 模式仅将等待抬到该场景档下限（15/20/30s），不叠加 60s；日常模式维持原规则。用户点击/拖拽仍执行 60s 安静期，优先于放置带来的 10s 首机会；放置不会消除尚未结束的用户输入抑制。睡眠/显示器失效清除 focus；暂停只冻结时钟、不重置等待。

场景模式只允许一个新增显著 run；不会与当前已有显著互动叠加。旧食盘/栖木仍沿用已实现的离栖机会，它们不是本次新增 focus，也不额外缩短计时。新 run 的全局 encounter 租约必须覆盖这些已有入口，若入口无法遵守租约，M6d 一并补齐 busy 准入测试。

新分支使用独立、固定盐值的引擎随机流；候选按鸟 ID、对象 ID 排序后采样。M6a 纯迁移必须保持现有回放摘要；M6d 调度变化后升级模拟语义版本并更新夹具，不要求仍产生 M5n 的随机结果。低频档 1% 不是每分钟 1%，也不承诺等待固定时长必然出现礼物。

所有新自动行为要求 `ambientEnabled`、相关开关开启、非 quiet、未暂停、未按鼠标键。姿态增强不占新机会。预览可绕过随机机会和冷却，但不能绕过开关、暂停、物种、几何、占用、熟客身份或素材校验；一次用户点击只启动一个访问/运输/整理步骤，不隐式补全整座巢。

### 2.4 接触、附着与场景容量

把当前 `HabitatObjectStore` 的单食盘限制改为**食盘/浴盆/巢台合计最多一个活动场景**。固定栖木保留独立三槽。放置另一类时返回 busy，界面提供“清除当前场景”再放置，不静默销毁用户物件。

携带复用的是附着/拾取/放置原语，不嵌套启动第二个行为 run：麻雀的 `leafCarry`、灰喜鹊的 `visitorGift`、斑鸠的 `nestMaterialCarry` 各自使用自己的物种准入，不能为了复用而给灰喜鹊开放独立叶片携带。

`CarriedObject` 记录稳定对象 ID、类型、拥有鸟 ID、当前状态（available/attached/placed/retired；placed 叶片仅在礼物准入通过时可再次 attached）和接触锚。附着位置由当前鸟姿态的喙锚推导。落点、飞行安全包络和遮挡判断取鸟与附着物的并集，不能只检查 48×48 鸟体；枝条旋转的极值也计入包络。拾取提交是原子的：同一 tick 从场景移除可拾取实体、扣对应库存并绑定鸟；放下时原子解除。取消携带时在当前可见位置淡出 0.2s 后回收；不坠落到不合法坐标、不从屏幕中央补生、不回滚出第二份对象。

新道具统一由正常渲染快照输出、沿用遮挡；不创建抢焦点窗口，不接管全局鼠标。用户主动放置的物件允许在指定处淡入；自动昆虫必须完整从屏外进入。固定树枝不提供双鸟求偶站位，巢台也不提供多人槽。

所有新场景的取消恢复有界：先取消 run 并释放参与者所有权，再调用已有安全飞行/找落点恢复；对象进入 retiring 后拒绝新访问并保留必要承载面，最多 2 个未暂停模拟秒后必须清理。暂停期间的删除/失效不保留这段延迟：立即解除场景承载引用并将鸟交回已有失效恢复状态，后续运动由原引擎暂停规则决定。若仍无落点，转入既有离场恢复路径，禁止悬空无限等待。恢复不延续原 run 的成功资格。睡眠/应用退出直接执行既有全局清理，不等待这 2s。

### 2.5 保存与版本

- 新增布尔设置缺失时按第 8 节默认值补齐，保留旧用户值；不重置 hoverDelay、pointerFollowEnabled、鸟数或概率。新增可选键不需要冒充不兼容的大版本迁移。
- 场景对象、运行实例、租约、水花、昆虫和未完工巢台不跨重启保存；固定栖木锚点继续沿用原有持久化。
- 手册新增行为 ID 后发布归档格式 v2：能读 v1 并迁移；旧程序不能覆盖 v2。现有 `ObservationEntry` 严格验证行为枚举，必须覆盖降级读取保护；不用“新增字符串不影响兼容”略过此项。
- 礼物额度单独保存，不能写进随机模拟时钟或观察手册；详见礼物规格。存储失败时停止自动礼物并显示原因，不影响普通鸟行为。

## 3. 姿态素材与已有行为扩展

### 3.1 十二种明确交付名单

M6b：麻雀 `treeSparrow`、珠颈斑鸠 `spottedDove`、家燕 `barnSwallow`、夜鹭 `nightHeron`。

M6c：白头鹎 `lightVentedBulbul`、红耳鹎 `redWhiskeredBulbul`、乌鸫 `chineseBlackbird`、鹊鸲 `magpieRobin`、暗绿绣眼鸟 `swinhoesWhiteEye`、灰喜鹊 `azureWingedMagpie`、红嘴相思鸟 `redBilledLeiothrix`、纵纹腹小鸮 `littleOwl`。

每种新增以下 10 个独立姿态名，共 120 张逻辑姿态；不含镜像重复、不含沿用旧帧。姿态是风格化产品表现，不把全部物种都画成同一种缩头幅度或鞠躬。

| 包 | 帧名（冻结） | 初始播放契约 |
| --- | --- | --- |
| A1 观察 | `lookNear`, `lookFar` | 沿既有 watch 的目标和期限，进入/退出各 0.15s；不重新计时或让头每帧随机抖动 |
| A2 警觉 | `alertRise`, `alertHold`, `alertRelax` | 起势 0.12s、放松 0.25s，中段用已有 alert 剩余期限；目标失效直接恢复 |
| B1 休息 | `restLower`, `restTuck`, `restWake` | 进入/退出各 0.25s，中段沿已有 rest；不同鸟保留自己的颈、腿、翼尾轮廓 |
| B2 起飞准备 | `takeoffCrouch`, `takeoffPush` | 0.25s + 0.20s，对接原 0.45s 预备；点击换位立即抢占，不等完整片段 |

不得通过延长原 run 造成额外冷却/观察计数；若剩余时长不足过渡，按剩余时长压缩过渡。A1 头部朝目标只表达有限偏转，整身方向仍由现有逻辑决定。

### 3.2 明确新增的已有行为支持

- 探头：新增白头鹎、鹊鸲；4 → 6 种。两者各补 `peekLower/peekLook/peekRecover` 三帧（共 6 张），取代其探头流程的 idle 复用；保持脚位并验证脖颈不会穿过窗口边缘。
- 固定栖木：新增白头鹎；6 → 7 种。三槽、单鸟容量和 128×24 逻辑树枝资产不变；用它实际体型重新计算安全余量，不仅添加名单。
- 追逐、空中结队：各新增红耳鹎；6 → 7 种。仅同种配对，保留独立退出与原目的地；不新增通用追逐帧。
- 同伴理羽继续仅家燕、暗绿绣眼鸟；种子食盘继续仅麻雀、珠颈斑鸠。二者不通过本批姿态包自动扩种。
- 其余 34 种保留现有表现；白眉姬鹟只新增后述捕虫专用包。每种处理意见见逐鸟矩阵，不留“以后统一适配”作为验收标准。

## 4. 新场景规格

下列物种、素材和行为细节以调研整合后的各小节为准。所有新增动作具有自动与明确的预览入口；预览不修改全局鸟种概率。

### 4.1 浴盆：麻雀、白头鹎（M6d）

依据：[水浴调研 S1–S3](research/SPECIES-ACTIVITY-EVIDENCE.md)。两种都有物种级水浴记录；本期只交付这两种。

- 对象：浴盆逻辑画布 128×40，水线/脚位由元数据标注，单槽；寿命 300s、最多三次访问。未完成访问不扣次数；正在访问时寿命耗尽则取消并安全离开，不突然删掉鸟脚下的表面。
- 条件：居民已站稳 ≥1s、安静 ≥8s、惊扰 <0.35，路线和盆周边能容纳该鸟完整图形；原宿主与盆都不能是遮挡中的安全死角。首次放置只进入 §2.3 的场景机会，不保证立即有鸟访问。
- 状态：预约→飞抵→观察 0.6s→试水 0.6s→低身 0.4s→洗澡 3×0.8s→抬身 0.4s→甩水 0.8s→安全离开并落稳。访问硬上限 35s，路线不足时间则拒绝。
- 资产：每种 `bathInspect/bathTouch/bathLower/bath0/bath1/bath2/bathRise` 共 7 帧；甩水复用已有 shake/stand。盆 1 张、水花 `splash0…3` 共 4 张。水花同屏最多 6 份、每份寿命 0.4s。
- 完成：洗澡阶段结束且鸟已安全离开盆并落稳才 completed、扣一次访问、手册记一次。失败后的应急降落不能把未洗完的 run 记成功。

### 4.2 静止叶片拾取与携带：麻雀（M6e）

这是明确的风格化物件互动，不声称麻雀自然界会按本流程把叶片搬给人。既有 B16 动态落叶追随继续保留；新增独立 `leafCarry`。

- 用户通过“放置叶片”选择普通窗口顶部或地面合法边缘；落点必须解析为稳定宿主和相对位置，不能把任意空中鼠标坐标当承载面。全局最多一枚可拾取叶片，拾取前寿命 180s；使用同一 `SceneProp` ID 贯穿携带，不新造复制品。
- 原场地另选距离 80–240 个逻辑点的合法放下位置；按当前 scale 缩放，屏幕空间不够直接拒绝；首版不跨屏。拾取前预约放下点，宿主轻微移动跟随锚点、失效取消。
- 状态：靠近→观察 0.4s→低头 0.3s→接触拾取 0.2s→抬头 0.3s→短途飞行→放下 0.4s→恢复 0.3s。硬上限 25s；物件放下后按 §2.3 的 8s/600s 规则保留，最后 0.2s 淡出回收。
- 资产：麻雀 `carryLook/carryLower/carryGrip/carryPlace` 4 帧；叶片 `leafToken` 1 张。对所有复用的 fly/land 帧补精确喙锚，不增加带叶烘焙版身体。
- 寿命切换：180s 只约束拾取前；原子拾取后停止旧到期倒计时，由 run 的 25s 上限管理附着物。放下提交时启动 8s/600s 展示寿命；随后礼物拾取同样停止该倒计时，礼物落到接收锚后另计 120s。
- 完成：放下且恢复结束才 completed。放下后被点击不撤销已放下的实体，仅取消行为计数；放下前取消按公共附着回收规则处理。清除叶片要同时找到 available/attached/placed 状态的实体。

### 4.3 捕虫：家燕与白眉姬鹟分批（M6f.1、M6f.2）

依据：[捕虫调研 S4–S6](research/SPECIES-ACTIVITY-EVIDENCE.md)。家燕采用连续飞行拦截；白眉姬鹟采用栖点出击并尝试返回。返回原点是产品收尾选择，现有来源未证明该物种每次回到同一栖点。两种是确定交付项，分别完成整批实现和验收。

共同目标：一只昆虫，4 帧 `insect0…3`，12s 寿命；从选定屏幕外进入，整个图形边界先在屏外，进入可见区后才可被捕获。不追逐真实鼠标、不生成血液或残骸。规划时确定目标轨迹和单次拦截窗口，飞行中不逐帧随机变向。

接触用喙锚的时间连续扫掠与虫碰撞圆（逻辑半径 3、按世界 scale 缩放），并尊重同一帧中的先后时间；只有真实接触才移除虫。计算只检测固定数量的曲线段，禁止无限求解。每次 run 最多一次拦截尝试；未捕获时安全恢复后以 failed / 新增 `missedTarget` 结束，另有诊断计数，不进观察手册。

- **M6f.1 家燕**：仅选择已有普通飞行中的居民；不抢占绕鼠标、追逐或其他拥有者。保存原飞行目标并验证从当前速度接入可行的局部轨迹，拦截段最多 4s；完成后继续原目标，原目标失效则普通安全落点。若速度/切线无法连续衔接，拒绝本次机会。预览可等待已有居民自然进入飞行，最多 10s，超时明确拒绝；不能强迫传送到空中。整个 run 上限 35s，捕获且恢复普通飞行目标后完成。
- **M6f.2 白眉姬鹟**：从普通窗口顶部/地面合法边缘起飞；不新增固定树枝资格。出击半径 80–220 逻辑点、拦截段最多 3s；预约原落脚点，成功或失败都尝试返回。原点失效则找安全落点，禁止穿越新障碍去追原点。整个 run 上限 25s；捕获且最终落稳才完成。
- 每鸟新增 `catchOpen/catchClose/catchRecover` 3 帧，并为复用飞行/落地帧补喙锚。吞咽只通过合喙恢复表达，不新增食物或健康系统。
- 昆虫到期/飞出屏幕使捕获失败；若鸟提前被点击，立即取消恢复，虫在剩余寿命内继续原路线并退出。关闭捕虫时连同虫立即清理。

### 4.4 熟客虚拟礼物：灰喜鹊（M6g）

此功能是**明确拟人化产品设计**，不宣称灰喜鹊会给用户送礼，也不使用“喜鹊喜欢闪亮物”作为依据。首版只有叶片礼物；默认关闭。

- 资格：现有熟客档案 `visits >= 3`、`familiarity >= 0.6`，当前居民是灰喜鹊且已站稳；仅本机该档案一次自动礼物，全局两次自动礼物提交之间至少 24h。不设每日签到或离开惩罚。
- 地点：用户已有的固定栖木至少一个有效、空闲。灰喜鹊不落上小树枝：在安全邻近路线经过并释放叶片，叶片落在树枝预定义接收锚；该物件不占鸟槽且最多存在一枚。物件/路线与正在访问的鸟冲突时拒绝。
- 开始前准备一次完整可行路线：首版灰喜鹊须先在合法普通边缘拾取用户已放置的叶片，再飞向接收树枝；不新增屏外持物入场变体。没有现成叶片时不在嘴里凭空生成。
- 复用携带素材契约：灰喜鹊 `carryLook/carryLower/carryGrip/carryPlace` 4 帧，复用 `leafToken`；所有带物飞行喙锚要独立适配。前段沿既有携带，释放 0.3s、叶片受控落到接收锚最长 0.8s，鸟继续安全飞行；run 上限 35s。礼物留 120s，可从设置清除；无弹窗、通知音或奖励货币。
- 额度协议：平台在申请时以稳定锁文件原子写入 `GiftLedger v1` 的 `(visitorArchiveSeed, visitorID)` 与 grantedAt；持久化成功后向引擎提交一次授权 token（token UUID、requestID、档案命名空间、鸟 ID、鸟种、来源、叶片 ID、接收栖木 slot/revision），额度在 token 发出时消费，取消不返还。写入失败/时钟倒退/其他实例已领取时拒绝，防止重启或双实例重复刷礼物。所有真正释放礼物都必须消费 token，token 不能重复使用。
- 异步申请：引擎一次只保留一个待授权 requestID。申请前完成几何预检；平台异步存储不阻塞 tick。返回时必须匹配仍存活的申请并重新检查鸟、素材、叶片、栖木和开关；点击、删除、禁用、超时或取消申请后，迟到 token 立即作废且已消费额度不返还。不得交给下一次申请使用；单次申请 5s 平台时限，结果进入引擎前作为外部输入录制，模拟内不自行读取墙钟。
- 账本永久保留全部已授权命名空间/档案键及全局最近授权时间，资格校验与写入在同一跨进程锁内完成，不能随着熟客128条缓存淘汰而丢历史。上限 10,000 条/2MiB；达到上限停止发放并显示原因，不裁掉旧键。
- 记录输入包含授权/拒绝结果和稳定 token，不让回放读取当前系统日期或真实文件。旧版本未知账本只读保护，不清空重建。首版不提供清空额度按钮；关闭熟客功能保留账本。若未来增加档案重置，必须一并设计身份命名空间迁移；本批不能隐式重置额度。
- 预览要求已有符合熟客条件的灰喜鹊及合法叶片/接收树枝，可使用仅内存 preview token；不消费自动额度，只记 preview。完成是叶片到达接收锚并可见；之后清除物件不追加观察记录。

### 4.5 求偶展示：珠颈斑鸠（M7a）

首版明确只做珠颈斑鸠，素材与动作依据见 [求偶/筑巢调研](research/COURTSHIP-NESTING-EVIDENCE.md)。现有通用 bow、双鸟招呼、同伴理羽不能当作这个新行为已完成。

- 两只同种、已站稳且安静 ≥10s 的居民，在同一普通顶部边缘或地面。使用双鸟完整转身图形边界，双方之间至少 12 个桌面点余量；足够的宿主长度、无遮挡、鼠标离双方图形外扩 80 逻辑点区域。不使用单鸟固定栖木或巢台。
- 角色为 initiator / observer，只控制这次动画；不推断雌雄、成年年龄或永久配偶。产品说明“取材于求偶展示的风格化片段”，不把 observer 的停留记为交配或繁殖成功。
- 状态：双方朝向 0.4s→发起者抬身 0.5s→鞠躬展示 2×1.0s→观看者转头观察 0.5s→双方恢复 0.6s，总计 4.0s；硬上限 6s。配对采样只在开始时进行一次。
- 新帧 `courtRaise/courtBow0/courtBow1/courtBowRecover/courtObserve` 共 5 张，首版不做飞行求偶、不播放叫声、不叼食互喂。脚锚保持，鞠躬时颈部和斑点纹理连续，不只平移头部。
- 任一方失效即全组取消，另一个恢复合法当前状态。完成只记录 `courtshipDisplay`，不增加熟客亲密度、配对表或繁殖资源。

### 4.6 巢材运输与简化筑巢：珠颈斑鸠（M7b、M7c）

首版同样只做珠颈斑鸠的小型枝条平台，依据见 [求偶/筑巢调研](research/COURTSHIP-NESTING-EVIDENCE.md)。独立“巢台”道具与三槽固定树枝分开；不把同一树枝贴图当作所有鸟的巢。

**M7b 运材闭环：** 用户放置一个 144×48 逻辑画布的巢台（合法地面或普通顶部边缘，单鸟槽），附带三根枯枝的材料盘。材料盘逻辑画布 32×16，中心相对巢台水平 120 逻辑点，先尝试左侧再右侧，整组须在同一屏幕合法承载区；不够空间则放置失败。对象寿命 900s，库存 3；运输一次不代表筑巢完成。

每次从当前居民中选一只珠颈斑鸠：预约材料点和巢台→飞抵材料→观察 0.4s→低头 0.3s→叼住 0.2s→抬起 0.3s→飞抵巢台→放下 0.4s→恢复 0.3s→离开并落稳。run 上限 35s。在喙触枝并转为 attached 的同一个提交点扣库存；拾取前取消不扣，拾取后取消回收附着枝条并把该根记为耗损，库存不返还、不自动补充。用户可清除重放场景，不存在必须做完的任务。

每鸟仅一根枝条；翼/尾运动不能让枝条穿过身体。珠颈斑鸠新增 `carryLook/carryLower/carryGrip/carryPlace` 4 帧；道具 `twigToken` 一张，逻辑长 16 点，短于鸟身。放下提交时转为“已送达待整理”，不在 M7b 宣称巢完成；完成且安全离开才记一次 `nestMaterialCarry`。放下后被点击/超时仍保留可整理材料，仅不记运输完成。对象存续期间始终满足 `可用 + 附着 + 待整理 + 已整理 + 耗损 = 3`；清除对象时将未完成部分回收，不增添材料。

**M7c 枝条整理：** 扩展同一对象，增加 0/1/2/3 四个巢进度状态；0 复用空巢台，1–3 各一张 overlay。运输 run 结束并释放租约后，只要有已送达待整理材料（无论运输是否记 completed），下一次符合条件的机会即可安排整理一根；同一 run 不重复记录运输和筑巢两种完成。

`nestBuild` 与运材共用巢台 focus 的机会：若有未整理的送达材料，优先整理；否则尝试运材，不二次抽概率。整理状态：预约巢台→从当前合法落点飞抵并停稳→朝向 0.3s→低头调整 2×0.6s→压实 0.4s→抬身 0.3s→安全离开，硬上限 30s。新增 `nestPlace/nestAdjust0/nestAdjust1/nestSettle` 4 帧。进入抬身前的原子提交点消费一根已送达枝条，进度 +1；重复 tick/取消/回放不得重复消费。

巢进度在第三根提交时达到 3 即显示完成的小平台，是否计本次观察完成由最终退出结果独立决定；不孵蛋、不出现幼鸟、不生成伴侣。每次完整整理且离开安全才记一次 `nestBuild`；第三次另加 UI“巢台完成”显示状态，不再额外记第四次行为。提交点之后被点击，巢进度保留但该 run 不记 completed；对象清除/到期则取消鸟的访问并整体回收，安全恢复完成后移除承载面。剩余时间不足完成路线则不再接受新访问。

## 5. 素材制作与性能约束

所有新帧名只追加到对应物种的 `speciesFrames`，公共 34 帧的名称/索引不变。旧鸟种未编辑帧应逐像素保持。使用现有 `SpeciesArt.swift` / `DetailedBirdArt.swift` 的可编辑绘制源；生成图可用于道具和动作参考，不能用一张整图替代多帧、身份一致性、脚锚及喙锚验收。

每个包交付：源文件、帧清单、接触元数据、导出图集、左右方向联系表、0.5×/1×/2×循环预览、实际原生图层截图。放大图好看不等于桌面原始尺寸可辨。水花、昆虫、叶片、树枝与鸟体分图层，不把临时物件烘焙进永久鸟体。

CPU/内存无虚构绝对目标：使用同机同鸟数 M5n 基线；固定样本运行重复三次，报告中位数和最差回调 p95/p99。新功能关闭时，性能中位数超过基线 10% 必须解释并复测；这属于排查阈值，不作为跨设备硬件承诺。对象/租约/图层在完整退出后回到基线，长时内存不得呈持续增长。

## 8. 设置、提示与观察手册

本阶段沿用现有设置窗口；设置分组为“基础姿态”“双鸟互动”“场景与物件”“熟客”。显示支持鸟种文字与未满足预览条件，不增加复杂逐鸟概率编辑器。

| 设置键 / 控件 | 默认 | 生效与预览 |
| --- | --- | --- |
| 新姿态 | 跟随已有 watch/alert/rest/takeoff 开关 | 无重复总开关；保存后应用 |
| `bathEnabled` | true | “放置浴盆 / 清除 / 预览洗澡”，没有道具就不自动发生 |
| `leafCarryEnabled` | true | “放置叶片 / 清除 / 预览携带”；与动态落叶追随入口区分 |
| `insectCatchEnabled` | true | 总环境互动开关控制自然触发；“预览家燕捕虫 / 预览白眉姬鹟捕虫”分别选择物种；未交付按钮不展示 |
| `visitorGiftsEnabled` | false | 用户开启后才可能自然发生；预览标注模拟礼物，必须已有熟客身份，绕过额度但不写额度 |
| `courtshipEnabled` | true | 受 `socialInteractions` 总开关控制；“预览求偶展示”，需两只珠颈斑鸠 |
| `nestBuildingEnabled` | true | 仅在用户放置巢台后可发生；“放置巢台 / 清除 / 预览运材 / 预览筑巢” |

放置流程采用现有三秒采样鼠标模式，取消/关闭设置/重置/保存均撤销待采样回调；新场景物件在应用世界中创建，不能混同于尚未保存的固定栖木位置草稿。放置失败保留现有物件，并显示 noSpace/busy/missingFrames 对应中文说明。

新手册类别固定为：`bathVisit` 洗澡 / Bathing、`leafCarry` 携带叶片 / Leaf Carrying、`insectCatch` 捕虫 / Insect Catching、`visitorGift` 熟客礼物 / Visitor Gift、`courtshipDisplay` 求偶展示 / Courtship Display、`nestMaterialCarry` 运送巢材 / Nest Material Delivery、`nestBuild` 筑巢片段 / Nest Building。

放置物件是用户命令，之后自然访问仍记 automatic；点击“预览”启动的 run 记 preview。新姿态沿用原类别，不把 120 张帧当作 120 个新行为。新行为须完成定义中的最终可见步骤才可计数；巢材/筑巢具体提交点见对应规格。

## 9. 明确暂缓项

- 完整性别、配偶、繁殖季、交配、蛋、孵化与幼鸟；求偶展示只是一段有来源依据的风格化互动。
- 家燕泥巢、喜鹊大型穹顶巢、啄木鸟凿洞、鹭类大型树巢等专用建造场景；不套用小型树枝巢。
- 把全部 46 种开放给浴盆、食盘、栖木、求偶或同伴理羽；逐鸟矩阵明确保留既有支持的范围。
- 第 47 种新物种、复杂行为树编辑器、外部动作脚本、实时音频、触摸屏交互、Windows 引擎。

这些是有意排除的本期范围，不需要后续 agent 自行补齐。需要纳入时另立规格、素材和验收批次。
